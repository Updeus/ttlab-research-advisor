\section{Backend and persistence}

FastAPI registers public and protected routers; SQLModel maps entities to SQLite. Startup rejects authoritative indexes whose active generation, corpus, configuration, file hash, role, or coverage is invalid. \texttt{/health} reports liveness; \texttt{/ready} separately reports database, retrieval, public-projection, and deployment controls without exposing local paths.

RAG answers retain question, answer, retrieved evidence/citations, provider/model/configuration, corpus/retrieval identity, grounding/support states, warnings, timestamps, and review metadata. Structured recommendations retain the profile, ranked evidence, gap/suggestion boundary, scope, skills/data/risk/evaluation fields, provenance, and review state. Public Idea Generator turns are request-scoped: the response retains provider/model, prompt/configuration hashes, corpus/retrieval identity, source chunks, basis, warnings, and time, but the endpoint does not persist the conversation. Public serializers omit technical hashes, paths, private notes, and restricted evidence.

\section{Retrieval modes}

Keyword retrieval uses SQLite FTS5 and its \texttt{bm25()} rank, with a deterministic token-frequency fallback. Feature hashing maps lower-cased alphanumeric tokens through signed SHA-256 buckets into 256 L2-normalised dimensions. Learned dense retrieval uses the pinned \texttt{all-MiniLM-L6-v2} encoder and 384-dimensional L2-normalised vectors. Long chunks are encoded as overlapping 254-token windows, mean pooled, and renormalised. Query/chunk similarity is cosine similarity.

The heuristic hybrid combines normalised keyword/vector scores with metadata, section, evidence, topic, and diversity terms; historical tuning selected keyword 0.10 and dense 0.80 on development MRR. APIs expose four accurately named modes and source/freshness diagnostics. The dense runtime caches a validated matrix by atomic pointer/manifest signature, ranks vectors before hydrating only the selected SQLite rows, and invalidates the cache when the active generation changes. Public retrieval applies the independent production projection before fusion and rejects stale chunk bytes, generations, or publication state. A loopback-only demo preview is a separately labelled configuration, not a silent fallback.

\section{Question answering and citation checks}

\Cref{fig:rag-workflow} traces Ask. A fixed evidence-coverage rule abstains before composition when a question is not answerable; explicit paper scope handles referential wording. The reproducible provider is offline extraction. Claim decomposition prunes unused citations and records \texttt{support\_unverified} until atomic review, so locator validity cannot silently become entailment.

The optional Ask adapter requires the effective Ollama policy, rejects pre/post digest drift, and claims generation-time digest verification only when the response reports it; otherwise it records a mutable-tag limitation. Provider failure yields a visible extractive fallback. Paper-scoped Ask augments generic referential prompts with the selected paper title before retrieval. The historical service was unavailable, so no model-quality or latency comparison is claimed.

The verifier checks identifiers, generation membership, exact current chunk bytes, page locators, fields, and lexical overlap. Its status is structural grounding; AI-silver review assesses support, citation choice, coverage, and abstention separately.

\section{Conversational Idea Generator}

The current public \codepath{/extensions} route is a conversational Idea Generator rather than the structured Finder form. A request contains a message of at most 2,000 characters plus at most twelve prior user/assistant turns and 6,000 history characters. The backend builds a query from the current message and up to three recent user turns, runs keyword retrieval at depth twelve, applies the fixed answerability gate, and retains at most six unique paper sources. The conversation remains browser/request state and is not written to recommendation history.

The local model must return one to three schema-validated ideas containing a title, research question, summary, fit rationale, MVP, skills, evaluation plan, and source aliases. The prompt explicitly prohibits novelty, guaranteed-feasibility, and supervisor-endorsement claims. Every alias is resolved only against the retrieved evidence map. Invalid labels are replaced and warned; an idea with at least one valid alias is \texttt{paper\_informed}, otherwise it is a \texttt{general\_suggestion}. A cited paper therefore supplies background or inspiration, not proof that the proposal is novel, feasible, or supported by that paper.

Idea generation is intentionally strict: it uses the approved local Ollama provider and does not silently fall back to extraction or an external service. Production requires an approved tag/digest; an explicit local demo may permit installed models while recording the observed digest. The service checks identity before and after generation, requests JSON-schema output, makes one bounded repair attempt, returns a retryable 503 when the provider/identity is unavailable, and returns a retryable 502 after two invalid structured responses. Runtime provenance records corpus scope, retrieval strategy, source chunks, prompt-template/configuration hashes, provider/model identity, digest attestation state, and timestamp.

This feature was implemented after the frozen v1/v2 evaluations. Four source-derived formative prompts exercise RAG, agriculture, out-of-corpus, and multi-turn scoping behavior, while backend and frontend tests verify schemas, alias filtering, provenance, no-match labeling, failure states, and transient UI behavior. They are regression fixtures rather than gold judgments and do not establish live-model quality, usefulness, novelty, or feasibility.

\section{Thesis Extension Finder}

The finder accepts interests, skills, time, project/data constraints, difficulty/topics, retrieval mode, and result count. It groups evidence by paper and scores retrieval 0.30, interest/topic 0.20, skills 0.15, data/time/difficulty 0.10 each, evidence 0.05, and avoided topics $-0.20$. These are heuristics, not learned student-success estimates.

Each output separates paper-supported work, explicit/inferred/missing gap, and suggestion; it includes scope, skills, risk, data assumptions, evaluation, citations, and review. Time, access, and feasibility remain candidate-specific unknowns unless sourced. Evidence-only mode stops before generation and supplies the baseline in \cref{fig:recommendation-workflow}.

\subsection{Finder requirement and failure contract}

The Finder's input contract rejects an empty interest set, bounds list/text lengths, validates enumerated difficulty/project/data values, normalizes weights, and constrains result count. The public \codepath{POST /api/recommendations/extensions} call always uses \texttt{persist=False}; protected history/detail calls require a reviewer actor. The browser echoes the submitted profile and mode so a user can detect stale or misapplied constraints. It retains the last successful result while a refresh is in progress and exposes a retry action after failure.

\section{Topics, authors, artifacts, and review}

The explorer uses a controlled \TopicVocabularyCount{}-label taxonomy with source evidence; a dense prototype provides comparison. Author-topic scores use eligible technical publications, while anonymous serialization applies the public projection and never falls back to hidden relations. Related-paper ranking combines shared topics/authors, metadata, lexical overlap, and optional vectors.

The deterministic artifact generator produces public and technical summaries, contributions, methods, limitations, future work, suggested extensions, skills, evaluation plans, and text podcast scripts. Fact, inference, and suggestion types are explicit. Unreviewed generated artifacts may be shown only with an explicit unreviewed-AI warning; corrected replacements enter the public projection only after approval. The Phase 4 review processed every \GeneratedRagAnswerCount{} historical RAG answers, \GeneratedRecommendationCount{} recommendation runs, and \GeneratedArtifactCount{} artifacts. It regenerated evidence-safe artifacts/recommendations where configuration was sufficient; historical RAG configuration was insufficient, so those \GeneratedNeedsReprocessCount{} records were preserved and marked \texttt{needs\_reprocess}. A disposable replay created \GeneratedReviewEventCount{} new hash-chained events, reused \GeneratedReviewReusedCount{} existing output-version events, and verified \GeneratedReviewVerifiedEventCount{} events without mutating the live database. A second pass changed \GeneratedReviewSecondPassChangedCount{} rows, demonstrating idempotence within that replay boundary.

\section{Frontend and evidence communication}

The route-based frontend provides all principal public and protected routes. Screens expose source locators, provider/model/time, grounding/review, freshness, generated notices, and empty/error/retry/offline states. Feature switches remove disabled routes from navigation while the corresponding API returns a stable \texttt{503 feature\_disabled} response; protected diagnostics remain available. Production public emptiness is labelled as an approval/rights boundary, and local-demo previews carry a persistent insecure-demo warning. Evaluation separates historical from identity-bound current evidence. Profiles and Idea Generator turns are transient, and automated tests cover semantics, focus, reduced motion, alternatives, and responsive layouts.

Public and protected routes deliberately have different data lifecycles. Ask, structured Finder, and Idea Generator calls are transient and expose no public history. Admin Control uses a local account session: the opaque session token is HttpOnly, the readable CSRF cookie is echoed only on state-changing requests, and the browser never receives the password hash. Service bearer actors remain supported for scoped automation. The protected interface exposes review queues plus feature switches, admin-account state, local-model inventory/digest policy, bulk preview/execute, publication preview/execute, and ingestion-sync controls according to actor capability.

\section{Generated-output governance and deployment boundary}

Admin mutations require authenticated roles and CSRF for session actors; production fails closed without HTTPS and an admin actor, and AI actors cannot issue human states. Bulk review and publication first persist an actor-bound preview hash with a ten-minute expiry; execution recomputes the candidate state and returns conflict rather than apply a stale preview. Catch-all review still excludes missing-PDF records. A process-local primitive lock safely spans FastAPI worker-thread handoff, while a database-scoped no-follow file lock serializes review-event mutation/hash/commit across local processes. Neither is distributed consensus. The dedicated sync worker can stage and process scheduled candidates, but whole-corpus atomic promotion remains fail-closed. TLS termination, institutional identity, distributed limiting, monitoring, backup, and incident operations remain deployment responsibilities.
