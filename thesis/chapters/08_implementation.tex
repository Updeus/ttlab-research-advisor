\section{Backend and persistence}

FastAPI registers papers, search, Ask, local-model status, recommendations, artifacts, topics/authors, evaluation, and protected admin routers. SQLModel maps entities to SQLite and applies additive compatibility migrations. Startup validates security configuration, creates tables, and rejects present authoritative indexes whose corpus, configuration, file hash, or coverage is invalid. \texttt{/health} reports process liveness; \texttt{/ready} separately reports database, keyword, feature-hashing, and optional dense readiness without exposing local paths.

JSON-like response fields remain structured across the service boundary. RAG answers retain question, answer, retrieved chunks/papers, citations, provider/model, grounding state, warnings, unsupported-claim list, timestamps, and review metadata. Recommendations retain the submitted profile, ranked papers, evidence, gap class, system suggestion, MVP/stretch scope, skills, data needs, risk, difficulty, evaluation plan, provider, and review state.

\section{Retrieval modes}

Keyword retrieval uses SQLite FTS5 and its \texttt{bm25()} rank, with a deterministic token-frequency fallback. Feature hashing maps lower-cased alphanumeric tokens through signed SHA-256 buckets into 256 L2-normalised dimensions. Learned dense retrieval uses the pinned \texttt{all-MiniLM-L6-v2} encoder and 384-dimensional L2-normalised vectors. Long chunks are encoded as overlapping 254-token windows, mean pooled, and renormalised. Query/chunk similarity is cosine similarity.

The heuristic hybrid combines normalised keyword/vector scores with hand-authored metadata, section, evidence, topic, and diversity terms. The tuned configuration retains those terms but sets keyword weight to 0.10 and dense weight to 0.80 based on development MRR. Search APIs and UI expose \texttt{keyword}, \texttt{feature\_hashing}, \texttt{dense}, and \texttt{hybrid}; they return mode, expanded query, component scores, manifest/freshness diagnostics, snippets, pages, sections, and warnings.

\section{Question answering and citation checks}

\Cref{fig:rag-workflow} traces an Ask request. The default reproducible answerer is offline and extractive: it orders retrieved sentences by intent and composes a bounded response. An Ollama adapter can call a local model with a source-restricted prompt and temperature 0.1; provider failure produces a visible fallback. \section{Thesis Extension Finder}

The finder accepts interests, skills, time, project type, data constraints, preferred difficulty/topics, avoid-topics, retrieval mode, and result count. It retrieves an expanded candidate set, groups evidence by paper, and computes a deterministic score: retrieval relevance 0.30, interest/topic match 0.20, skill match 0.15, data/time/difficulty 0.10 each, evidence strength 0.05, and an avoid-topic penalty of 0.20.

Each output separates paper-supported baseline work; explicit, inferred, or missing gap evidence; and a system-suggested extension. It includes MVP, stretch goals, skills, risks, data assumptions, evaluation plan, citations, warnings, and review state. An evidence-only mode returns ranked papers and passages without a generated extension, providing both a safer user choice and the experimental baseline shown in \cref{fig:recommendation-workflow}.

\subsection{Finder requirement and failure contract}

The Finder's input contract rejects an empty interest set, bounds list/text lengths, validates enumerated difficulty/project/data values, normalizes weights, and constrains result count. The public \codepath{POST /api/recommendations/extensions} call always uses \texttt{persist=False}; protected history/detail calls require a reviewer actor. The browser echoes the submitted profile and mode so a user can detect stale or misapplied constraints. It retains the last successful result while a refresh is in progress and exposes a retry action after failure.

Failure states are explicit. No candidates can indicate over-constrained interests, unavailable indexes, or no eligible evidence; it does not trigger advice without papers. \section{Topics, authors, artifacts, and review}

The explorer uses a controlled \TopicVocabularyCount{}-label lexical taxonomy, including an other-or-unknown label, with synonym rules and source-weighted evidence. A learned-dense prototype compares paper primary-source centroids with label prototypes at a development-selected threshold. Author-topic scores aggregate only eligible publication-topic links under canonical identities. Related-paper ranking combines shared topics/authors, venue/year proximity, lexical overlap, and optional vector similarity.

The deterministic artifact generator produces public and technical summaries, contributions, methods, limitations, future work, suggested extensions, skills, evaluation plans, and text podcast scripts. Fact, inference, and suggestion types are explicit. The Phase 4 review processed every \GeneratedRagAnswerCount{} historical RAG answers, \GeneratedRecommendationCount{} recommendation runs, and \GeneratedArtifactCount{} artifacts. It regenerated evidence-safe artifacts/recommendations where configuration was sufficient; historical RAG configuration was insufficient, so those \GeneratedNeedsReprocessCount{} records were preserved and marked \texttt{needs\_reprocess}. \GeneratedReviewEventCount{} hash-chained events record the corrections. A second pass changed zero rows, demonstrating idempotence.

\section{Frontend and evidence communication}

The route-based frontend provides Dashboard, Paper Browser/Detail, Search, Ask TTLAB, Thesis Extension Finder, Topic/Author Explorer, Evaluation, and protected Admin Review. Relevant screens expose paper/chunk/page/section evidence, provider/time, grounding and review status, data/index freshness, generated-content warnings, and empty/error/retry/offline states. Profile inputs are not stored by default. Keyboard focus, semantic landmarks, form labels, reduced-motion behavior, chart alternatives, and 360/768/1024/1440-pixel layouts are covered by automated tests.

Public and protected routes deliberately have different data lifecycles. Ask and Finder send one transient request and do not expose history endpoints. Admin Review is rendered only after a reviewer token is entered; the token is held in module/page memory, attached only to protected requests, and is never written to local or session storage. Reloading clears it. This browser behavior supplements---but does not replace---the backend's bearer validation and role checks.

This mapping clarifies the residual human boundary. Automated checks can detect a missing label, hidden focus, unauthorized status code, persistence regression, or absent warning. They cannot establish whether a student understands the distinction between inferred gap and paper-stated future work, whether a screen reader workflow is efficient, or whether a supervisor considers an extension feasible. Those outcomes belong to a later ethics-approved study and independent accessibility assessment.

The requirement--API--test mapping is the authoritative interface evidence. Screenshot assets remain useful development records, but they are omitted here because a rendered state cannot establish behavior across failures, authorization states, viewports, or assistive technologies. The executable contracts in Appendix~\ref{app:schema-api} make those boundaries inspectable without treating a screenshot as evaluation.

\section{Generated-output governance and deployment boundary}

Admin mutations require reviewer/admin authentication except when an operator explicitly enables a loopback-only insecure demo. Production configuration fails closed without HTTPS and an active admin actor. Human and AI actors have distinct reviewer types; AI actors cannot issue reviewed/approved/rejected human states. The threat model covers path traversal, SSRF, PDF bombs, XSS, injection, secrets, rate limits, logging, backups, dependency auditing, and correction/incident procedures. A reverse proxy, TLS termination, monitoring service, and production identity provider remain deployment responsibilities, not repository claims.
